# 주제: 리눅스 네트워크 진단 명령어 (ping, traceroute)

## 학습 목표
* 리눅스 서버 환경에서 다른 서버 및 외부 인터넷(ex.구글)과의 통신 상태 점검
* 대표적인 네트워크 진단 명령어인 `ping`과 `traceroute`의 개념 및 사용법 습득

---

## 1. ping (Packet Internet Groper)

### 1) 개념
* 특정 IP 또는 도메인을 가진 목적지 서버가 살아있는지(Alive 상태), 통신 지연 시간(Latency)이 어느 정도인지 확인하는 명령어
* 내부적으로 ICMP(Internet Control Message Protocol) 프로토콜의 Echo Request / Echo Reply 메커니즘 사용

### 2) 사용방법
* **윈도우와의 차이점:** 윈도우에서는 4번 전송 후 자동 종료되지만, **리눅스에서는 별도 옵션이 없으면 무한 전송**됨
* **종료 방법:** `Ctrl + C` 키를 눌러 직접 중단
* **개수 지정 옵션 (`-c`):** 원하는 횟수만큼만 패킷을 보내고 종료

```bash
# 기본 실행 (무한 전송 -> Ctrl+C로 종료)
ping google.com

# 3회만 패킷을 보낸 후 자동 종료
ping -c 3 google.com
```

---

## 2. traceroute
### 1) 개념
* 내 컴퓨터(발신지)에서 목적지 서버(수신지)까지 데이터 패킷이 도달하기 위해 거치는 모든 중간 경로(라우터 및 게이트웨이)를 추적해 주는 명령어
* 네트워크의 어느 구간에서 지연이나 병목\ 현상이 발생하는지 진단할 때 활용

### 2) 사용방법
```bash
# 1) traceroute 패키지 설치 (Rocky Linux 9 기준)
dnf install -y traceroute

# 2) 경로 추적 실행 (-I 옵션: ICMP 프로토콜 사용)
traceroute -I google.com
```
**💡 -I 옵션을 사용하는 이유:**
traceroute 기본값은 UDP 프로토콜을 사용하지만, 많은 기업 및 ISP 방화벽에서 UDP 패킷을 차단한다. 이 때, ICMP 방식(-I)을 사용하면 응답을 받을 확률이 더 높아진다고 한다.

* **0번째 줄**
  - Hop(홉): 패킷이 한 라우터(네트워크 장비)에서 다음 라우터로 건너가는 단위
  - 30 hops max: traceroute 명령어의 기본 최대 홉 수 설정값. 무한 루프에 빠지는 것을 방지하기 위한 안전장치

* **2번째~23번째 줄**
  - 중간 라우터나 보안 장비(방화벽)에서 보안상의 이유로 ICMP 응답/패킷 통과를 차단하도록 설정되어 있기 때문에 출력되는 무응답 표시

* **24번째 줄(tv-in-f100.~)**
  - 응답 시간 (46.720 ms): 내 서버에서 출발해 24개의 라우터를 거쳐 구글 최종 서버에 도달 후 돌아오기까지 약 0.046초가 걸렸음을 의미
  - google.com이 아니라 도메인명 (tv-in-f100...)이 뜨는 이유 (Reverse DNS): google.com은 대표 서비스 이름(회사 정문)일 뿐이며, tv~는 실제로 요청을 처리해 준 컴퓨터의 고유 이름(구체적인 부서명)
  - 대규모 서버 과부하를 막고 빠르게 응답하기 위해 서버를 분산시켜서 요청을 처리
