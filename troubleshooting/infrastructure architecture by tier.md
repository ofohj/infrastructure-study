# 헷갈렸던 내용
▶ 하나의 서버, was, db가 연결되면 3-tier 아키텍처라고 생각했다. 그러나 티어는 가상머신 단위로 계산되기 때문에, 한 서버 안에서 was와 db를 연결시켰다면 이는 1티어 아키텍처인 것이다.

# [개념 공부] 티어 구조

💡인프라 아키텍처에서, 티어는 **‘물리적(또는 가상머신 단위로)으로 서버 장비가 얼마나 독립되어 있는가?’**를 기준으로 삼음

[참고] 소프트웨어의 분리는 ‘레이어’임. 

## 1. 지금까지 구현한 상태: 1-Tier, 2-Layer 구조

- Client(사용자): 내 진짜 윈도우 컴퓨터
- Server(서버): rocky linus 가상머신 1대
    - 이 안에 톰캣(WAS)과 MariaDB가 살고 있음

## 2. 3-Tier 아키텍처 예시

### 🦉 구조

- 1티어: Web 서버(Nginx, Apache 등)
    
    ▼ 1계층은 2계층에 명령, 데이터 요청
    
- 2티어:  WAS(tomcat)(비즈니스 로직 처리)
    
    ▼ 2계층은 3계층에 쿼리 요청
    
- 3티어: DB(MariaDB)(데이터 저장소)

### 🦉 설명

1) 1티어(웹 서버) - Presentation Tier
    - 사용자 브라우저의 요청을 가장 먼저 맞이하는 문지기
    - 정적인 화면만 처리하고, 로그인이나 데이터 처리가 필요한 요청은 WAS로 넘김
2) 2티어(WAS) - Application Tier
    - 톰캣이 구동되는 서버
    - 비즈니스 로직(자바 코드)을 계산하고 분석
3) 3티어(DB) - Data Tier
    - MariaDB가 돌고 있는 서버
    - 데이터의 입출력 담당

### 🦉 설명

💡실제로 3-Tier 구현하려면?

- 가상머신을 최소 3대 이상 켜서 web, was, db 3가지 영역이 서로 독립된 환경에 존재해야 함
- 이 때, 각 VM끼리 통신할 수 있도록 방화벽 포트를 개방하고, IP 기반으로 연결해주어야 함!!
